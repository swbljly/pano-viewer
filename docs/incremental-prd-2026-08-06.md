# 增量 PRD：pano-viewer 远程链接查看与收藏

## 元信息

| 项 | 内容 |
|---|---|
| 产品 | `pano-viewer` — 360° 等距圆柱（equirectangular）全景图片查看器（Android） |
| 包名 | `com.example.panoviewer` |
| 文档类型 | 增量 PRD（简单版，无竞品分析） |
| 基线能力 | 本地文件选择 / 系统「打开图片」intent → base64 dataURL → `loadImageDataURL` |
| 本次范围 | 新增「链接查看」与「收藏链接」两类增量能力 |
| 产出人 | 产品经理 许清楚（Alice） |
| 日期 | 2026-08-06 |
| 建议落盘路径 | `pano-viewer/docs/incremental-prd-2026-08-06.md` |

## 1. 产品目标

让安卓用户通过**夸克分享链接（含提取码）、网页链接、图片直链**三种方式，无需手动导出文件即可在 `pano-viewer` 中查看远程全景图片，并能将感兴趣的**链接**（不含图片本体）收藏，随时一键重新查看。

## 2. 用户故事

| # | 角色 | 故事 | 价值 |
|---|---|---|---|
| US-1 | 普通用户 | 作为用户，我想粘贴夸克分享链接并输入提取码，从解析出的文件列表中选一张全景图查看 | 不用下载到本地即可看分享的全景图 |
| US-2 | 普通用户 | 作为用户，我想粘贴一个网页链接，由 APP 抓取 HTML 并解析出 `<img>` 列表供我选择查看 | 不用自己找图的原图地址 |
| US-3 | 普通用户 | 作为用户，我想直接粘贴图片直链，APP 下载并立即渲染为全景图 | 最快路径看一张已知直链图 |
| US-4 | 普通用户 | 作为用户，我想把当前链接收藏起来（自动记标题） | 下次不用再粘贴 / 解析 |
| US-5 | 回头用户 | 作为用户，我想在收藏里点一条，直接重新加载并查看 | 一键复看，省去重复操作 |

## 3. 需求池（P0 / P1 / P2）

> **统一约束**：所有远程图最终都经 **Android 端下载字节 → 转 base64 dataURL → `evaluateJavascript` 注入 `window.PanoViewer.loadImageDataURL(dataURL)`** 渲染。不直接用 WebView 内 `loadImageUrl` / `?image=` 远程拉取（file:// 下被 CORS 拦截）。

### P0（必须，MVP）

| ID | 需求 | 说明 / 用户体验 | 验收标准 |
|---|---|---|---|
| P0-1 | 新增「链接」入口 | 主查看器顶部工具栏新增「链接」按钮，点击进入链接输入与解析流程 | 入口可见、可进入、可返回 |
| P0-2 | 支持三类链接输入 | 同一输入框接受：夸克分享链接、网页链接、图片直链（自动识别类型） | 三种链接均可提交解析 |
| P0-3 | 夸克分享解析（含提取码） | 识别为夸克分享且需提取码时提示输入；解析后列出文件供选全景图 | 有码能输入并解析；列出可选项 |
| P0-4 | 网页图片抓取解析 | 识别为网页链接时，APP 内抓取 HTML 并解析 `<img>` 列表供选择 | 解析出图片地址列表 |
| P0-5 | 图片下载并注入渲染 | 用户选定后，Android 下载字节 → base64 → 注入 `loadImageDataURL` 渲染 | 选中图能在全景区渲染 |
| P0-6 | 收藏（增 / 删 / 查，本地持久化） | 仅存「链接 + 标题」，不缓存图片本体；支持新增、删除、查询 | 重启后收藏仍在；不占图片空间 |
| P0-7 | 从收藏一键重新加载查看 | 收藏列表点击即按原链接重新下载并渲染 | 一条点击即可复看 |

### P1（应有，体验闭环）

| ID | 需求 | 说明 | 验收标准 |
|---|---|---|---|
| P1-1 | 解析结果文件列表选择 UI | 夸克 / 网页解析结果以列表呈现，可勾选 / 单选 | 可明确选择目标图 |
| P1-2 | 提取码输入 UI | 仅在需要时显示，标注「夸克分享提取码」 | 有码必填、无码不挡路 |
| P1-3 | 错误 / 超时 / 空结果提示 | 解析失败、下载超时、无结果时给明确文案 | 三种异常均有提示 |
| P1-4 | 收藏列表 UI 与空状态 | 收藏页展示链接卡片（标题 + 地址截断）；无收藏显空状态引导 | 空 / 非空状态均合理 |
| P1-5 | 返回主查看器 | 链接层 / 收藏页均可返回全景查看主界面 | 返回不丢当前查看状态 |

### P2（可选，增强）

| ID | 需求 | 说明 |
|---|---|---|
| P2-1 | 解析历史 | 记录近期解析过的链接，便于复用 |
| P2-2 | 批量收藏 | 解析结果可多选后一次性收藏 |
| P2-3 | 收藏导出 / 分组 | 导出收藏链接；或按分组管理（可列入 P2，本期可不实现） |

## 4. UI 设计稿（文字 + ASCII）

### 4.1 主查看器（现状 + 增量）

```
┌─────────────────────────────────────────────┐
│ [≡]   全景查看器          [🔗 链接] [⭐ 收藏] │  ← 新增两按钮
├─────────────────────────────────────────────┤
│                                             │
│           (Three.js 全景渲染区)             │  ← 现状保留
│                                             │
├─────────────────────────────────────────────┤
│ [ 选择本地图片 ]  [ 打开图片 ]               │  ← 原有入口保留
└─────────────────────────────────────────────┘
```

### 4.2 「链接」输入与解析层（Bottom Sheet / 对话框）

```
┌─ 添加链接 ───────────────────────────── [✕] ┐
│ 链接 URL                                      │
│ [ https://pan.quark.cn/s/xxxx 或 网页/直链 ]  │
│ 提取码（可选）[ _______ ]  仅夸克有码时必填   │
│ [ 解析 ]                                      │
│ ── 解析结果 ──                                │
│ ☑ 海边全景.jpg          12.3 MB   [图片]      │
│ ☑ 城市夜景.png           8.1 MB   [图片]      │
│ ☐ readme.txt              (非图片·置灰)       │
│ [ 查看选中 ]   [ ☆ 收藏选中 ]                 │
└─────────────────────────────────────────────┘
```

### 4.3 「收藏」页 / 列表

```
┌─ 我的收藏 ───────────────────────────── [✕] ┐
│ (空状态) 还没有收藏，去「链接」里收藏吧        │
│ ── 或 ──                                     │
│ ⭐ 夸克分享-海边全景                           │
│    https://pan.quark.cn/s/xxxx  [打开][删除]  │
│ ⭐ 网页-城市夜景                              │
│    https://site/.../night.jpg     [打开][删除]│
└─────────────────────────────────────────────┘
```
说明：点击「打开」即按链接重新下载并渲染；「删除」移除该收藏（仅删链接记录，不影响远端）。

## 5. 待确认问题（需用户 / 架构师拍板）

1. **夸克非官方接口风险**：夸克解析依赖非公开接口，存在失效 / 风控 / 验证码风险。失败时应如何向用户呈现？是否引导改用「直链」或「网页链接」方式？
2. **收藏是否分组**：本期按「扁平列表 + 标题」实现；是否需要文件夹 / 标签分组？分组列入 P2，是否提前？
3. **直链防盗链**：直链若需 `Referer` / `Cookie` 等防盗链校验，当前「安卓下载再注入」方案能否携带自定义请求头？不支持时如何提示？
4. **夸克文件筛选范围**：解析出的文件是否只筛图片类型（jpg / png / jpeg / webp）供选？非图片是否显示但置灰？
5. **大图 / 超时策略**：下载超时阈值与进度反馈如何定义？超大图（如 >50MB）是否限制或强提示？
6. **收藏失效处理**：收藏链接重新打开时若返回 403 / 404 / 超时，报错文案与引导（如「链接可能已失效」）？
7. **选前预览**：解析结果是否需缩略图预览再决定是否查看，还是选中即直接渲染全景？
8. **一键收藏当前图**：是否需要从「正在查看」状态直接收藏当前链接，而不必回到链接页？
9. **链接识别规则**：三类链接（夸克 / 网页 / 直链）的自动识别判据（域名特征 vs 后缀特征）由谁定义？是否允许用户手动指定类型？

## 附：范围边界与复用约定

- **不涉及**：重写现有本地文件选择、系统「打开图片」intent、Three.js 球体贴图渲染等已有核心能力。
- **强制复用**：远程图统一走 `loadImageDataURL(dataURL)` 注入；不新增 WebView 内远程拉图路径。
- **技术实现留白**：用哪个网络库、收藏用 Room 还是 SharedPreferences、HTML 解析方式等由架构师决定，本 PRD 仅描述「做什么与用户体验」。
